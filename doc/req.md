# 波利亚解题思路交互菜单设计

针对以波利亚解题思路为核心、采用类似 AI 代码解释工具的交互方式，菜单与按钮的设计应围绕**降低认知负荷**、**揭示思考过程**、**促进主动提问**展开。以下从通用能力、分阶段特色功能、以及辅助学习工具三个层面进行分析。

## 一、通用菜单（选中任意步骤均可出现）

这些菜单项帮助学生从多个角度理解当前这一步「在做什么」和「为什么这么做」。

| 菜单/按钮 | 功能说明 |
| --- | --- |
| 解释这一步 | 用自然语言说明该步骤的数学含义，像代码解释器一样，把公式、代数操作「翻译」成人话。 |
| 这一步的目的 | 明确说明这一步在整体解题计划中的作用，它想达成什么中间目标，对应波利亚的「拟定方案」逻辑。 |
| 为什么这样做 | 回溯推理链，展示从已知条件到这一步的逻辑依据，揭示「如何想到」的过程。 |
| 查看详细推导 | 如果原步骤有跳步，展开所有隐藏的代数变形、定理引用等细节，支持折叠/展开。 |
| 还有其他方法吗 | 针对当前局部操作，提供替代的数学处理方式（如另一种恒等变形、换元、定理选择），并比较优缺点。 |
| 检验这一步 | 对当前结果进行快速验算，比如代入特殊值、量纲检查、逆运算验证，像代码测试一样即时反馈。 |
| 提问 / 追问 | 弹出一个对话输入框，学生可针对这一步输入自己的疑问，引擎以对话方式回答，保持上下文。 |
| 复制 / 标记 | 将步骤内容或整个解释复制到剪贴板，或高亮保存为「疑难步骤」，方便日后复习。 |

## 二、按波利亚四阶段的专属菜单

根据解题进程的阶段，额外提供与该阶段教学目标匹配的按钮。

### 1. 理解题目阶段（Understanding）

**目标：** 确保学生真正读懂题目，明确已知、未知、条件。

| 菜单/按钮 | 功能说明 |
| --- | --- |
| 拆解题干 | 高亮并逐句解读题目文本，标记条件、目标、隐含假设。 |
| 画图 / 可视化 | 自动生成几何图形、表格、数轴或示意图，将文字转为图形表征。 |
| 用自己的话重述 | 生成一个口语化的题目重述，并请学生确认是否理解一致。 |
| 找出关键信息 | 提取已知量、未知量、约束条件，用列表呈现。 |
| 类似题目 | 检索一道条件或结构相似的例题，只展示题目（不展示解法），让学生类比。 |

### 2. 拟定方案阶段（Devising a Plan）

**目标：** 训练策略性知识，让学生看到「思路是如何形成的」。

| 菜单/按钮 | 功能说明 |
| --- | --- |
| 思路怎么来的 | 展示解题策略的启发式来源，比如「看到二次三项式，想到配方或求根」「看到和差，可尝试化为积」等。 |
| 尝试过的失败路径 | （元认知训练）披露常见的错误尝试，说明为什么走不通，帮助学生理解正确路径的选择过程。 |
| 相关的模型/题型 | 指出当前问题可归结为哪类已知模型（如追及问题、最值求导、整体换元），并给出模型框架。 |
| 拟定子目标 | 将大问题拆成若干小目标，当前步骤服务于哪个小目标，可视化进度。 |
| 先猜后证 | 给出一个探索性的猜测（如「这里可能有个对称点」），让学生先感受，再继续严格推导。 |

### 3. 执行方案阶段（Carrying out the Plan）

**目标：** 保证运算正确，理解每一步操作细节，并能纠正错误。

| 菜单/按钮 | 功能说明 |
| --- | --- |
| 展开代数细节 | 把一个长推导展开成最小的可操作单元，比如移项、合并同类项、因式分解，每一步都可单独点击。 |
| 检查计算 | 对该步进行符号运算验证，若有常见错误（符号、系数、分母忘记乘），高亮并提示。 |
| 此步用了什么定理/公式 | 显示引用的数学定理（如勾股定理、洛必达法则）的全称和前提条件，确保前提满足。 |
| 修改参数试试 | （交互式探索）将某个常数替换成滑块变量，让学生观察输出变化，理解这一步的敏感性。 |
| 另解延续 | 在此步骤分叉，展示一种不同的执行路径，并允许继续沿着该路径走完，形成解法的对比树。 |

### 4. 回顾与反思阶段（Looking Back）

**目标：** 巩固迁移能力，检验答案，深化理解。

| 菜单/按钮 | 功能说明 |
| --- | --- |
| 验证答案 | 将最终答案代回原题检验，或通过另一种方法重新得到答案并对比。 |
| 还有别的解法吗 | 展示至少一种全局性的不同解法（如几何法与代数法），并用并排界面比较。 |
| 推广/变式 | 提出问题：「如果改一个条件，答案会怎样？」生成一个变式题目并附带简要分析。 |
| 这道题教会我们什么 | 总结关键思想、技巧或思维误区，像代码审查的「learnings」，可收藏。 |
| 生成同类练习 | 基于本题，自动生成一个结构相同、数字或情境不同的练习题，可一键跳转练习。 |

## 三、辅助学习工具与导航按钮

除了基于选中步骤的浮动菜单，界面全局也应提供辅助理解的常驻按钮：

- **解题流程导航条：** 显示波利亚四阶段的进度圆点，可随时跳转，但会提示「已执行步骤可能需重新审题」。
- **思维导图模式：** 将整个解题过程的逻辑链、子目标、分支解法展示为可交互的思维导图，点击节点选中步骤。
- **历史记录 / 撤销：** 允许回溯到之前的状态，对比不同路径下的中间结果。
- **难度调整滑块：** 控制解释的详细程度（如「简洁版 / 详细版 / 初学引导版」），实时刷新所有解释文本。
- **全局提问：** 一个始终可见的对话图标，可针对整个题目发问，不受选中步骤限制。

## 设计原则总结

- **可解释性优先：** 任何一步都必须能被「解释」和「追问」，这是 AI 解题引擎的核心价值。
- **多层次信息：** 一个步骤同时提供「是什么（操作）」「为什么（理由）」「还能怎么办（变体）」「怎么想到的（启发式）」，由按钮按需展开。
- **主动学习触发：** 按钮不只是「解释」，更鼓励学生「检验」「换方法」「自己提问」，促使深层加工。
- **错误友好：** 即使正确步骤也预设「常见错误」，学生点开可以看到「如果做错了会怎样」，这符合波利亚「回顾」中反思错误的理念。

---

通过上述菜单与按钮的组合，插件能够将静态解题过程转化为一个探究式对话环境，真正帮助学生像数学家那样思考，而不仅仅得到答案。
