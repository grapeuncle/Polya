# 提示词：开发基于波利亚解题思路的 Cursor 数学辅导插件

## 项目目标

开发一个 Cursor 插件（VS Code 扩展），将数学解题过程转化为**波利亚四阶段**式的交互辅导体验。用户选中任意解题步骤时，界面上会浮现类似 AI 代码解释工具的菜单/按钮，帮助学生深度理解解题思路。插件需使用 TypeScript 和 VS Code Extension API，采用 Webview 实现交互界面，并与 AI 引擎（通过后端服务或直接调用 LLM API）通信。

## 核心需求概览

- **解题引擎**：可调用外部 AI 或内置规则，生成符合波利亚四阶段（理解题目 → 拟定方案 → 执行方案 → 回顾）的步骤化解题过程。
- **交互亮点**：用户点击任意解题步骤，浮出上下文菜单，提供解释、追问、验证、替代方法、可视化等功能，菜单项根据当前所处阶段动态调整。
- **界面布局**：左侧或底部为题目输入区，主区域显示解题步骤列表，顶部有阶段导航条。每个步骤可展开详细推导，选中后弹出浮动工具栏（菜单）。
- **学习辅助**：支持思维导图模式、难度调节、全局提问、常见错误预设、生成同类练习等。

## 插件架构设计要求

1. **扩展入口**：在 `package.json` 中注册命令 `polya-solver.start`，激活后打开 Webview 面板。
2. **Webview 技术栈**：推荐使用 React + TypeScript，通过 `@vscode/webview-ui-toolkit` 保持 UI 风格一致。状态管理可用 React Context 或 Zustand。
3. **通信机制**：Extension 主进程与 Webview 之间通过 `postMessage` 传递数据；Webview 将用户操作（选中步骤、点击菜单）发送给主进程，主进程调用 AI 服务后返回结果，或由 Webview 直接调用 API（需处理密钥安全）。
4. **AI 接口抽象**：定义一个 `ISolverEngine` 接口，包含方法如 `generateSolution(problem: string)`、`explainStep(stepId, context)`、`checkStep(stepId)` 等。默认实现可调用 OpenAI / Anthropic API，需处理流式响应和错误。
5. **步骤模型**：每个解题步骤的数据结构应包括：

   ```typescript
   interface SolutionStep {
     id: string;
     phase: 'understanding' | 'devising' | 'carrying-out' | 'looking-back';
     content: string;          // 显示的主要文本，支持 Markdown 或 LaTeX
     rawLatex?: string;
     subSteps?: SolutionStep[]; // 可折叠的详细推导
     metadata: {
       objective?: string;     // 该步目的
       heuristic?: string;     // 启发性思路
       theoremApplied?: string;
       commonMistake?: string;
       alternativeApproach?: string;
     };
   }
   ```

6. **阶段状态**：整个解题过程由一个状态机管理，包含 `currentPhase`、`completedPhases` 等，确保导航清晰。

## 详细菜单与按钮设计（重点）

### 一、通用菜单（选中任意步骤时均显示）

以下按钮应出现在浮动工具栏中，每个按钮触发不同动作：

- **解释这一步**：将 `content` 扩展为口语化自然语言解释，必要时调用 AI 生成，展示在步骤下方的卡片中。
- **这一步的目的**：显示 `metadata.objective`，若为空则请求 AI 补全。
- **为什么这样做**：请求 AI 回溯推理链，解释从已知到此步骤的逻辑依据。
- **查看详细推导**：展开 `subSteps`，若无则调用 AI 生成代数/公式跳步的逐步展开，支持折叠。
- **还有其他方法吗**：请求 AI 针对当前局部操作给出至少一种替代处理方法，并比较优劣，以对比卡片呈现。
- **检验这一步**：对当前结果进行快速验算（代入特殊值、量纲检查等），将过程显示出来，若发现错误则高亮提示。
- **提问 / 追问**：弹出输入框，学生键入问题后，针对此步骤上下文调用 AI 给出回答。
- **复制 / 标记**：复制步骤内容到剪贴板，或将此步骤标记为「疑难步骤」（存储到全局状态，可统一查看）。

### 二、按波利亚四阶段的专属菜单

根据步骤所属的 `phase`，额外显示对应按钮。

#### 1. 理解题目阶段 (`understanding`)

- **拆解题干**：高亮并逐句解读原始题目文本。
- **画图 / 可视化**：根据题目生成几何图形、表格或示意图（用 Mermaid 或 SVG 呈现）。
- **用自己的话重述**：以学生口吻重述题目，并确认理解一致。
- **找出关键信息**：提取已知量、未知量、约束，列表展示。
- **类似题目**：仅展示一道结构类似的题目（不展示解法），供类比。

#### 2. 拟定方案阶段 (`devising`)

- **思路怎么来的**：展示策略启发来源，如「见到二次三项式想到配方」。
- **尝试过的失败路径**：解释常见错误尝试及为何不通。
- **相关的模型/题型**：指出本题可归类为何种数学模型，给出框架。
- **拟定子目标**：将解题路径拆解为子目标图，当前步骤高亮。
- **先猜后证**：给出一个猜测性结论，让学生感受猜想过程。

#### 3. 执行方案阶段 (`carrying-out`)

- **展开代数细节**：将当前步骤分解成最小操作单元（移项、合并同类项等），每个单元可单独点击。
- **检查计算**：进行符号运算验证，标注潜在计算错误。
- **此步用了什么定理/公式**：展示定理全称和前提条件检查。
- **修改参数试试**：提供参数滑块，交互式改变常数观察输出变化。
- **另解延续**：在此分叉，展示并执行另一种解法，生成对比树。

#### 4. 回顾与反思阶段 (`looking-back`)

- **验证答案**：将最终答案代回原题或换法验证。
- **还有别的解法吗**：全局展示不同解法，并排比较。
- **推广/变式**：生成「如果改一个条件...」的变式题。
- **这道题教会我们什么**：总结关键思想或思维误区。
- **生成同类练习**：基于本题生成结构相同的新题。

### 三、全局辅助工具与导航

- **阶段进度导航条**：四个圆点，点击可跳转，但切换时会提示可能需要重新审题。
- **思维导图模式**：切换视图，以交互式思维导图展示步骤逻辑、分支、子目标，点击节点等同于选中步骤。
- **历史记录与撤销**：在侧边栏显示操作历史，支持回滚。
- **难度调节滑块**：控制解释详细程度（简洁/标准/详解），修改全局状态，所有解释文本同步刷新。
- **全局提问**：浮动按钮，可对整个题目提问。

## UI 设计要求

- 浮动菜单必须紧贴选中步骤，类似 VS Code 的「灯泡」或代码操作菜单，也可设计为步骤右侧的浮动按钮组。
- 步骤支持 Markdown 渲染，数学公式使用 KaTeX。
- 配色需适应 VS Code 主题（浅色/深色）。
- 面板左侧预留题型输入区，可折叠；右侧主区域显示带可交互步骤的卡片列表。
- 点击步骤空白处高亮该步骤，并触发浮动菜单；点击菜单外区域关闭。
- 详细解释、替代方法等可展开为内嵌卡片或侧边抽屉，避免遮挡。

## 开发任务拆解

请生成完整插件项目代码，包含以下文件与模块：

- **`package.json`**：扩展清单，定义命令、激活事件、视图容器。
- **`src/extension.ts`**：主入口，注册命令，创建 Webview Panel，处理消息。
- **`src/SolverEngine.ts`**：AI 引擎接口与默认实现（可先提供 mock 数据）。
- **`src/webview/` 目录**：React 应用源码。
  - **`App.tsx`**：主布局，阶段导航，解题步骤列表。
  - **`components/StepCard.tsx`**：单个步骤卡片，支持选中、高亮。
  - **`components/FloatingMenu.tsx`**：根据当前阶段和步骤渲染菜单按钮，处理点击事件。
  - **`components/MenuActions/`**：每个菜单项对应的组件或处理函数（如 `ExplainStep.tsx`）。
  - **`store/`**：状态管理，包含题目、步骤、阶段、选中步骤、UI 设置等。
  - **`utils/api.ts`**：调用 AI 服务的封装函数。
- 必要的样式和类型定义。
- 配置文件（如 `.vscodeignore`）及 README 说明安装和使用方式。

## AI 接口调用规范

- 系统提示词应内置波利亚教学理念，每次请求需携带完整对话上下文（题目、已进行阶段、步骤历史）。
- 流式响应应在 Webview 中逐步显示，避免长时间等待。
- 错误处理：若 AI 调用失败，显示友好提示并允许重试。

## 注意事项

- 所有解释性内容必须默认使用中文。
- 确保 LaTeX 公式在 Webview 中正确渲染（使用 KaTeX CDN 或打包）。
- 插件包体积尽量小，避免不必要依赖。
- 考虑为教师提供「隐藏部分解释」的可配置项。
- 代码须遵循 TypeScript 最佳实践，并添加充分注释。
